# Trading Journey research import

This panel republishes only sanitized public-market news from existing ChatGPT research. It neither performs new research nor calls Coinbase, OpenAI or news APIs. Existing RSS panels remain independent.

## Hourly agent procedure

1. Read the latest completed reports in Trading Journey / Bitcoin trading strategy using the connected task reader. If research is represented only by content-reference cards, use the signed-in Chrome conversation UI and read those rendered reports and citation popovers. Never read browser cookies, internal network endpoints, or hidden application state. Never modify the original research schedule or trade permissions.
2. Capture the ORIGINAL research date, time and timezone. Do not confuse notification delivery, browser retrieval, publication or import time with research time. Only use actual completed report content, never an assistant's claim that a report ran. If source access fails, do not invent content or refresh any timestamps.
3. Extract only public news/risk coverage and source URLs from the report. Compose short attributed paraphrases, not full articles. Preserve source/event dates and uncertainties. Do not infer news for uncovered coins. Market-wide risk may be tagged MARKET; coin-specific items use their ticker. No new news API or independent research is needed.
4. Editorial privacy review is mandatory: exclude all personal holdings, balances, cost basis, P&L, order identifiers, prices of personal resting orders, execution instructions, account names, keys and private chat links. Never persist a raw transcript in this repository. The validator is only defense in depth, not sufficient privacy review.
5. Work in an isolated clean checkout of current origin/main; preserve unrelated user changes. Use apply_patch to create a sanitized temporary JSON report outside docs with exactly researched_at and items (see docs/journey-news.json). Run `python3 journal/journey_import.py INPUT` then `python3 journal/journey_import.py --check` and `python3 -m unittest discover -s journal -p test_journey_import.py`. Identical timestamps/content are no-ops. Do not rewrite history, change dates on duplicates or overwrite newer reports. Keep up to 168 reports.
6. Review the precise JSON diff for privacy and source fidelity. Stage only docs/journey-news.json; run the existing credential hook without bypassing it; commit and push the scoped change. If origin advanced, reapply the sanitized report against the new origin so concurrent portfolio/news updates are preserved. Do not force push. GitHub Pages publishes docs on push. Confirm the live JSON matches the committed artifact before claiming publication. Failures must not advance the source timestamp.
7. No new content means no commit. Stay quiet for unchanged or successful routine imports. Notify only on an actionable failure, missing source access, or deployment failure.

## Runtime / freshness contract

The hourly task is a Codex desktop heartbeat using a signed-in browser: it requires the computer and app running and usable ChatGPT browser access. It is not a cloud-to-cloud guarantee and cannot run while this machine is off. The page polls every minute, preserves source timestamps, and re-evaluates freshness every 15 seconds. After 90 minutes, current research is hidden and the report remains available explicitly as history. Fetch/validation failures also hide current research. History is retained separately from live portfolio data, and imported claims are labelled not independently verified. Source publication times may be unknown or older; never call all sources fresh because a report is recent.
